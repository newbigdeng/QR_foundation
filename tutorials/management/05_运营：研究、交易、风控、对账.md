# 05 运营：研究、交易、风控、对账

量化公司的日常不是“盯盘”，而是**让一条可复现的流水线每天稳定跑**。一人公司尤其要把运营做成“即使自己状态不好也不会出错”的系统。

## 一、日/周/月节奏

### 每日

| 时间 | 动作 | 产出 |
|---|---|---|
| 开盘前 | 数据更新、持仓/保证金检查、系统健康检查 | 开盘检查表 |
| 盘中 | 执行监控、异常告警、kill switch | 事件日志 |
| 收盘后 | 成交/持仓/现金对账、PnL 归因 | 日对账单 |
| 睡前 | 备份、日志归档、明日计划 | 运行记录 |

### 每周

- 策略表现：收益/回撤/波动/换手/滑点；
- 交易质量：成交率、拒单、延迟、冲击；
- 研究进展：假设、实验、失败记录；
- 运营事故：次数、原因、修复。

### 每月

- 完整 PnL 归因：市场/因子/选股/成本；
- 风险报告：VaR/ES、压力、集中度、杠杆；
- 财务：费用、税、现金流；
- 策略评审：继续/降权/停用。

## 二、研究流水线

```text
想法 → 假设卡 → 数据检查 → 回测 → 稳健性 → 模拟/前向 → 小资金 → 放大
```

每一关都要有“停止规则”：

- 数据泄漏/样本不足 → 停止；
- 扣费后无正期望 → 停止；
- 换标签/换品种不成立 → 降级；
- 前向 3 个月不达预期 → 回炉；
- 小资金实盘滑点/回撤超限 → 停用。

**不要把“回测好”直接等同于“上线”。**

## 三、变更管理

任何上线变更都要有：

- 变更说明（改了什么、为什么）；
- 影响范围（策略/品种/账户）；
- 回滚方案（代码/配置/数据版本）；
- 审批记录（一人公司也要留痕）；
- 变更后观察期（至少 1 周）。

## 四、事故管理

### 事故分级

| 级别 | 例子 | 响应 |
|---|---|---|
| P0 | 无法平仓/超额亏损/账户异常 | 立即停机、人工介入 |
| P1 | 数据断流/执行失败/对账大差异 | 1 小时内处理 |
| P2 | 单个策略异常/告警 | 当日处理 |
| P3 | 报表/日志/文档问题 | 本周处理 |

### 事故复盘模板

```text
时间线：
影响：
根因：
为什么没提前发现：
修复：
防止再发：
责任人/截止日：
```

## 五、权限与安全

- 交易/资金/数据权限分离；
- 密码/密钥不入代码库；
- 双因素认证；
- 关键操作日志；
- 离职/外包人员权限回收；
- 备份异地保存。

## 六、KPI（一人公司版）

| 指标 | 目标 |
|---|---|
| 系统可用率 | > 99.5% |
| 对账差异 | 0（当日解释清楚） |
| 滑点/模型差 | 在预算内 |
| 事故 P0/P1 | 0 / 季度 |
| 研究→上线周期 | 可度量、不无限拖 |
| 策略衰减 | 提前发现，不等到大回撤 |

## 七、一人公司的日历示例

```text
07:30 数据/系统检查
08:30 开盘前持仓/保证金/风险检查
09:00–15:00 执行监控 + 研究（低干扰时段）
15:30 对账/PnL
16:30 研究/复盘
20:00 夜盘检查（如有）
21:30 备份/日志/明日计划
```

## 八、检查清单

- [ ] 我有没有固定的开盘前/收盘后检查表？
- [ ] 每笔交易能否在 24 小时内对账？
- [ ] 每次上线是否有回滚方案？
- [ ] 事故是否有分级、复盘、防止再发？
- [ ] 我的权限/密钥/备份是否安全？

> 运营的目标不是“忙”，而是**让系统在你不盯盘时也不出错**。
