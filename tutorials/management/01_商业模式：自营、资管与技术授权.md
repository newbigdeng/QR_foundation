# 01 商业模式：自营、资管与技术授权

一人量化公司赚钱之后，通常会走到三条路。它们不是“哪个高级选哪个”，而是**资本、合规、能力、心态**四种约束下的选择。

## 一、三条路

| 模式 | 收入来源 | 规模上限 | 合规重量 | 适合阶段 |
|---|---|---|---|---|
| 自营（prop） | 自有资本收益 | 受自有资本和容量限制 | 低（不碰他人资金） | 起步、验证期 |
| 资管（manage money） | 管理费 + 业绩报酬 | 受 AUM、容量、渠道限制 | 高（登记/备案、适当性、托管、披露） | 有 2–3 年可审计业绩后 |
| 技术授权/软件 | 授权费、订阅、实施费 | 受产品化和销售能力限制 | 中（数据/IP/合同） | 有可复用工具链后 |

### 1. 自营

**公式**：

```text
净收益 = 资本 × 收益率 − 运营成本 − 税费
ROE = 净收益 / 自有资本
```

优点：简单、自由、不用对外披露、不用处理投资者关系。  
缺点：**资本有限，收益天花板明显**；一人公司还要承担全部回撤。

自营的核心不是“收益率越高越好”，而是：

- 回撤能否承受；
- 收益是否可持续；
- 容量是否够覆盖生活与再投资；
- 是否有 12 个月以上的现金储备。

### 2. 资管

收入变成：

```text
管理费 = AUM × 1%～2%
业绩报酬 = 超额收益 × 15%～20%
```

优点：用别人的钱放大收入，规模上限高。  
缺点：合规、托管、适当性、披露、投资者关系、赎回压力、策略容量、利益冲突，全都要处理。

**关键判断**：没有 2–3 年可审计、可复现的业绩记录，不要碰外部资金。  
“帮朋友管钱”在监管上也可能构成需要牌照/备案的资管行为，不要用“代客理财”绕监管。

### 3. 技术授权/软件

把回测、执行、风控、数据管道做成产品，卖给其他交易者/机构。

优点：不依赖资本，边际成本低。  
缺点：要产品化、支持、销售、合同、数据授权；客户会问“你自己怎么不用它赚钱”。

这条路适合“工具链确实比策略更强”的人，不适合把亏损策略包装成软件卖。

## 二、混合模式的风险

常见组合：

- 自营 + 资管：**利益冲突**（先给自己还是客户？）、容量分配、信息披露；
- 自营 + 软件：IP 归属、数据许可、客户是否成为竞争对手；
- 资管 + 软件：用客户交易数据做产品？合规红线。

混合不是不行，但要有**隔离墙**：

- 账户隔离、代码隔离、数据隔离；
- 关联交易披露；
- 同一策略的自营与资管容量分配规则；
- 员工/外包保密与竞业。

## 三、按资本阶段的建议

| 自有资本 | 建议模式 | 重点 |
|---|---|---|
| < 300 万 | 自营 | 低成本、验证 edge、保留现金 |
| 300–1000 万 | 自营 + 小团队 | 风控/运维/研究分工，考虑主体 |
| > 1000 万 | 自营 + 资管评估 | 合规/托管/审计/投资者关系 |
| 任意阶段 | 技术授权 | 只有工具链被外部验证后再做 |

**不要因为“别人都做资管”就去做资管。**  
资管是另一门生意：产品、渠道、合规、服务，和交易不是同一件事。

## 四、商业模式画布（一页版）

```text
客户：自己 / 外部投资者 / 机构客户
价值：稳定收益 / 低相关 / 定制策略 / 工具效率
收入：自营收益 / 管理费+业绩报酬 / 授权费
成本：数据、券商、软件、人力、合规、审计
渠道：自己 / 券商/FOF / 直销 / 合作伙伴
护城河：数据、执行、研究流程、AI 工作流、细分市场
关键风险：回撤、容量、合规、关键人、数据许可
```

## 五、检查清单

- [ ] 我现在的收入是否依赖单一策略/单一品种？
- [ ] 我的自有资本能承受多大回撤，仍不影响生活？
- [ ] 我是否有 12 个月运营现金储备？
- [ ] 我是否碰了外部资金？是否清楚相应合规要求？
- [ ] 我的工具链是否真的可产品化，还是只对我自己有用？
- [ ] 扩张时，我先加人、加资本，还是加产品？
